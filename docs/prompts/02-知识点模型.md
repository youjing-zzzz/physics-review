# Prompt #02 · 知识点模型：为什么表要这么设计

- 日期：D1
- 关联 commit：`feat(kp): 知识点数据模型与 SQLite schema`

## 我的疑问

> 我不会写 Python，只会用 Dify 做点工作流。这个东西的数据到底怎么存？

## AI 的回答要点

### 四张核心表，各管一件事

| 表 | 存什么 | 为什么单独存在 |
|---|---|---|
| `chapters` | 章节树（章/节，页码） | 用户拍的是目录，先落这里，才有"按章节缩小检索范围"的可能 |
| `kps` | 知识点（名称、类型、深度、认知成本） | 它是三档裁剪的最小单位，必须独立于章节存在 |
| `exam_stats` | 真题标注（年份、分值、题型、学校档次） | **原始数据**，重要性分数的唯一来源 |
| `kp_edges` | 前置依赖边 | 答错后回退，靠这张表 |

### 三个刻意为之的设计

1. **不存 `importance` 字段。**
   分数由 `schema.py::importance()` 实时算。存下来就会和 `exam_stats` 不一致，
   而且评委问"这个 0.62 哪来的"时没法回答。**可解释 > 省事。**

2. **`chunks` 挂在 `kp_id` 上，不挂在 `chapter_id` 上。**
   检索的最小单位必须和裁剪的最小单位一致，否则"这个块属于哪一档"要重新算。

3. **`questions.tier` 是冗余字段。**
   一道题可以同时服务 60 和 80 两档，但为了查询快，先按生成时的档位打标，
   后续用 `tier` 过滤。这是**已知的冗余**，写进文档而不是假装没有。

### 打分公式 v0

```
importance = 0.45·freq + 0.25·avg_score + 0.20·(1-cost) + 0.10·(1-prereq_len)
```

权重偏向"高频"而不是"高分"：期末里出现 5 次的选择题，比出现 1 次的压轴题更值得先学。
D4 会用真实真题分布重新校准这四个系数，并把校准过程写成表格放进技术文档。

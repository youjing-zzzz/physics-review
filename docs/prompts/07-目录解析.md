# Prompt #07 · 目录解析：结构识别与它够不着的地方

- 日期：D5
- 触发：想验证「拍任何课的目录都能用」
- 关联 commit：`feat(toc): 目录结构解析`、`docs: Prompt #07`

## 一个关键认知纠正

「图片转文字」和「图片转结构」是两件事：

| 阶段 | 说明 | 状态 |
|---|---|---|
| 图片 → 文字 | OCR，把像素变成字符 | 已通 |
| 文字 → 结构 | 目录解析，把字符变成章节树 | 本轮完成 |
| 结构 → 科目/知识点 | 联网确认这是哪门课的哪一节 | 未做 |

## 目录解析器（`backend/app/toc.py`）

主路径用**编号**而不是关键词，因为编号是科目无关的结构信号：

```
^\s*(?:第\s*)?(\d{1,2}(?:[.．·・]\d{1,2}){0,3})\s*[)）]?\s*[.．·、,，:：\-—\s]*(.+?)\s*$
```

处理了实测遇到的噪声：

- 全角点 / 间隔号：`2．1`、`2·1` → 统一成 `2.1`
- 编号紧贴标题：`2.1二分法`
- **编号独占一行**：OCR 常输出 `2．2．1` 一行、`不动点迭代` 下一行，用 `pending` 机制拼接
- 标题尾部页码被识别成汉字：`二分法的计算步骤一` → 去掉尾字
- 水印行：`扫描全能王 创建`

输出带 `coverage`（识别行 / 候选行），低覆盖率意味着"这张图可能不是目录页"。

## 实测算出的问题：分辨率

第一版用的素材是 QQ 的**缩略图**（485×647）。OCR 结果：

```
2之不动点送代法      ← 其实是 2.2 不动点迭代法
I.1二分法原理        ← 其实是 2.1.1 二分法原理
2，1二分法           ← 其实是 2.1 二分法
```

放大对照实验（同一张图）：

| 处理 | 字符数 | 编号质量 |
|---|---|---|
| 原图 | 162 | 差，`2之`、`2，1` |
| 放大 2× | 199 | 明显改善，`2．2不动点迭代法` 正确 |
| 放大 3× + 灰度 | 226 | 更好，`第2章 非线性方程的数值求解` 正确 |

**结论：OCR 质量由输入分辨率决定，不是算法问题。** 手机原图通常 3000×4000，
比缩略图强一个量级；真机测试必须用原图，且 OCR 前应统一放大 2–3 倍。

## 原图实测结果（3072×4096 手机照片）

用原图重跑，OCR 文本几乎干净，解析出的章节树：

```
[2] 非线性方程的数值求解
  [2.1] 二分法
    [2.1.1] 二分法原理
    [2.1.2] 二分法的计算步骤
  [2.2] 不动点迭代法
    [2.2.1] 不动点迭代
    [2.2.2] 不动点迭代法的收敛性
  [2.3] 牛贝一割线法        ← "牛顿—割线法" 的 OCR 误认
    [2.3.1] 牛顿迭代公式及其几何意义
    [2.3.2] 牛顿迭代法的收敛性
    [2.3.3] 割线法
    [2.3.4] 牛顿法求解代数方程
  [2.4] 迭代加速与改善
```

第 2 章 12 个节点全部正确挂载，层级、父子关系、标题都对。

剩下的错误集中在第 1 章，全是 OCR 把数字认错：
`1.3.1` → `1.3口`、`1.2.2` → `。·2`、`1.3.2` → `I.3·2`。

**结论：结构解析已经不是瓶颈，OCR 的字符准确率才是。**
下一步要么做二值化/去噪预处理，要么换 PaddleOCR。

## 不在解析器里做的妥协


面对 `I.1` 这类"字母其实是数字"的错误，最容易被诱惑的写法是把 `I/l/|` 全局替换成 `1`。
**没有这么做**：这会在真实含字母的目录（如 `2.1 PID控制`）上引入新错误。
正确的解法是提升 OCR 输入质量，而不是在解析层打补丁。

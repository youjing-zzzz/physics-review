# Prompt #09 · 三档裁剪：v1 的算法是错的

- 日期：D7
- 关联 commit：`feat(tier)`、`feat(api)`、`feat(ui)`

## 需求原话

> 只要把老师画的目录一拍，就能自动生成考 80 以上、60 以上、50 以上分别要学的东西，
> 而且不要过于深入。

## v1 的错误（保留记录）

第一版把门槛写成升序：

```python
THRESHOLDS = {"50": 0.34, "60": 0.48, "80": 0.60}
for t in ["50","60","80"]:
    if score >= THRESHOLDS[t]: min_tier = t; break
```

跑出来的结果：**三档都是 11 个、192 分钟，完全一样**。

原因有两层：

1. 语义搞反了。分数越高代表"越是保底要学"，应该落在**最靠前的档（50）**；
   而升序门槛 + 取第一个满足的档，让所有高分点都进了 50。
2. 先验分数太集中（0.55–0.69），三个门槛全被跨过，等于没有区分度。

## v2 的修正

```python
TIER_ORDER = ["50", "60", "80"]
THRESHOLDS = {"50": 0.58, "60": 0.46, "80": 0.34}   # 降序
```

没有真题时**不再硬凑分数**，直接按类型映射：

```python
TYPE_TIER = {
    "定义": "50", "概念": "50",
    "方法": "60", "公式": "60", "定理": "60", "原理": "60",
    "分析": "80", "应用": "80", "推导": "80", "证明": "80",
}
```

理由：先验分数本来就是猜的，用猜出来的数字过门槛是"假精确"；
按类型定档至少能回答"为什么它在 50 档"——因为它是个定义。

## 实测对比（同一份目录）

| 画像 | 50 档 | 60 档 | 80 档 | 排除 |
|---|---|---|---|---|
| 普通本科（depth_cap=2，不许证明） | 8 个 / 117 min | 11 个 / 192 min | 11 个 / 192 min | 4 个 |
| 985（depth_cap=4，允许证明） | 8 个 / 117 min | 12 个 / 222 min | 15 个 / 312 min | 0 个 |

差异来自两条硬约束：普通本科把「不动点迭代法的收敛性」「数值稳定性」这类
深度 3 的知识点**直接排除**（不是排后面，是不学）。

这就是「不要讲太深」的可执行版本——一条可复算的规则，不是一句 prompt 请求。

## 仍然诚实的地方

- 没有真题数据时，界面会显示「类型先验」，不显示"考频"。
- 被排除的知识点单独列出来，并写明"深度超上限"，用户可以质疑并改画像。

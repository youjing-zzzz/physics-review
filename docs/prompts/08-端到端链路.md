# Prompt #08 · 端到端：一张照片变成可计算的数据

- 日期：D6
- 目标：完成链路的第三段「结构 → 科目/知识点」
- 关联 commit：`feat(course)`、`feat(kp)`、`feat(ingest)`

## 现在这条链路是通的

```
手机照片(3072×4096)
  → Windows OCR
  → 目录解析（章节树，16 节点）
  → 科目判定（数值分析 / 计算方法，置信度 1.0）
  → 知识点拆分（15 个，带类型/深度/成本）
  → SQLite（books 1 / chapters 16 / kps 14）
```

一条命令：

```powershell
python scripts/analyze_toc.py data/ocr-cache/orient/xxx.txt --save
```

## 三个模块的设计取舍

### 科目判定：本地指纹，不联网

| 方案 | 问题 |
|---|---|
| 让 LLM 判 | 每次答案可能不同，无法回归测试，还要 API key |
| 联网搜 | 依赖网络与搜索 key，延迟不可控 |
| **本地课程指纹** | 零成本、可复现、可解释；缺点是需要人工维护词表 |

指纹表覆盖 5 门课（数值分析、大学物理、高数、线代、数据结构），
每门 10–20 个高区分度词，权重 1–3。

**关键：双下限防误判。** 因为上次吃过"置信度 1.0 却完全判错"的亏，
这次要求「绝对得分 ≥ 4」「命中词数 ≥ 2」「比例 ≥ 0.5」三条同时满足，
否则返回 `unknown` 并给出候选，由前端让用户选。

实测：数值分析目录命中 8 个词（二分法、不动点迭代、牛顿迭代、割线法、
迭代加速、病态、有效数字、数值稳定性），得分 22.5，置信度 1.0。

### 知识点拆分：后缀规则，不靠模型

`2.3.2 牛顿迭代法的收敛性` 和 `2.1 二分法` 的学习成本差一倍，
这个差别直接决定它在三档里落哪一档，所以必须显式标注。

规则表 19 条，把标题后缀映射到 `(类型, 认知深度 1-4, 预计分钟)`：

| 后缀 | 类型 | 深度 | 分钟 |
|---|---|---|---|
| 定义 / 概念 | 定义/概念 | 1 | 10–15 |
| 原理 / 公式 | 原理/公式 | 2 | 20–25 |
| 步骤 / 方法 | 方法 | 2 | 30 |
| 定理 / 算法 | 定理/方法 | 3 | 35 |
| 收敛性 / 稳定性 / 条件数 | 分析 | 3 | 30 |
| 推导 / 证明 | 推导/证明 | 4 | 40 |

选规则而不是模型：**可测、零成本、错了能定位到具体哪条规则**。
模型留到规则覆盖不到时兜底（下一步接入）。

### 落库：一次导入 = 一本书 + 一棵树 + 一组知识点

`ingest.save()` 幂等：同一本书重复导入会先删旧章节（级联删知识点）再重建。

## 这次踩的坑

1. `chapters.level` 的 CHECK 只允许 1/2，但目录有三层（`2.1.1`）→ 放宽到 1–4。
2. 删库后直接 `connect()` 得到空文件，`no such table: books`
   → 入口统一先 `db.init_db()`（幂等）。
3. 知识点 `code` 用章节号拼，两个 OCR 误认成同一编号的节点会撞码
   → 目前 `ON CONFLICT` 覆盖（少一条知识点），属于已知缺陷，等 OCR 修好后自然消失。

## 遗留

- 知识点只有"名字和类型"，还没有"讲什么"→ 需要联网检索补 `contents`
- `1.3口数值稳定性` 这类 OCR 数字误认，仍会产生错误的章节号
- 没有前端：目前只有 CLI 和数据库

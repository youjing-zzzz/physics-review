# Prompt #05 · OCR 与章节定位：一路踩坑

- 日期：D4
- 目标：让扫描件照片 → 文字 → 具体章节
- 关联 commit：`feat(ocr)`、`feat(locate)`、`fix(scripts)`

## 为什么先做 OCR

三份真题里两份是扫描件（扫描全能王生成，无文字层）。这不是意外，而是**目标的常态**：
学生拍的重点页本来就是照片。所以 OCR 是主链路，不是附加项。

决策：先用 **Windows 自带 OCR**（`Windows.Media.Ocr`），不下载任何模型。
理由：零依赖、离线、中文支持良好；PaddleOCR 留作识别率不够时的升级路径。

## 踩坑记录（四个，都真实发生）

### 1. 扫描件没有文字层，但图片藏在 PDF 里
`pypdf` 抽出来是 0 字。改从 PDF 原始字节里找 `FFD8...FFD9`（裸 JPEG），
直接导出 11 张图，其中 200–360 KB 的才是试卷页，3–25 KB 的是水印。

### 2. PowerShell 5.1 把带中文的 .ps1 按 GBK 读
报错长这样：`Unexpected token '}'`、`Missing closing '}'`，但文件肉眼完全正常。
根因：文件是 UTF-8 **无 BOM**，PS 5.1 默认按 ANSI(GBK) 解析，中文注释被拆成乱码，
把引号和花括号一起带崩。
**修复：所有 .ps1 必须存成 UTF-8 带 BOM。**

### 3. `StorageFile.GetFileFromPathAsync` 在受限进程里被挡
`Await ... "One or more errors occurred."`，内部异常被吞。
**修复：自己 `[IO.File]::OpenRead` + `AsRandomAccessStream`**，绕开权限代理，稳定。

### 4. `confidence` 写成 property 又想赋值
`AttributeError: property 'confidence' has no setter`。
**修复：改成 dataclass 普通字段。**

另外还有个隐蔽的：`[IO.File]` 用的是进程工作目录，`Set-Location` 改的是 PS 位置，
两者可能不同 → 相对路径读写会失败。**统一用绝对路径。**

## 定位器的设计

不走向量检索，用**章节关键词指纹**：

- 每个关键词带权重（`转动惯量` 3.5，`速度` 1.5）
- 命中次数取 `1 + log(n)`，防止某个高频词把整章刷上去
- 置信度 = 本章得分 / 所有章得分之和
- 低于 0.45 判 `confirm`，让用户点一下确认

## 实测结果

| 输入 | 判定 | 置信度 | 说明 |
|---|---|---|---|
| 扫描件单页（25-26 卷第 1 页） | 第 4 章 刚体的转动 | 0.594 `confident` | 命中 力矩×6 / 转动惯量×1 / 角动量×1 |
| 整份试卷（24-25 卷全文） | `confirm` | 0.214 | 命中分散，合理：整卷本就横跨 4/5/7 章 |

**关键结论**：定位器能区分"单页只讲一章"和"整卷覆盖多章"，
后者不硬下结论，符合"低置信进 to-confirm"的设计原则。

## 已知局限

- 公式识别不出来：`F=Rcosωt` → `F=Rcosoti`。但是**定位只需要名词**（力矩/转动惯量），
  公式烂不影响章节判断；真要做公式，再上专用 OCR。
- 关键词表是手写的，覆盖 15 章，需要 D10 用真实照片回归测试补漏。

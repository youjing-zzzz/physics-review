# Prompt #04 · 对标分析：DeepTutor 与女娲补天

- 日期：D3
- 触发：我提出「先别做，先学学别人」
- 关联 commit：`docs: 对标分析（DeepTutor/女娲补天）与复现步骤（AI #05）`

## 我给出的对标材料

1. **DeepTutor**（HKUDS，2.9 万 star，Apache-2.0）：面向长期学习的 AI 工作区。
   Chat / Solve / Deep Research / 知识库 / Quiz / Mastery Path / 记忆 / Skills。
   核心是"讲解—练习—反馈—复习"的 Agent Loop 与掌握度追踪。
2. **女娲补天（nuwa-mends-the-sky）**：面向大学期末突击的 Codex skill。
   输入 PPT/讲义/教材章节/作业/题库/往年卷 → "先建骨架、再压缩、再自测、再回补"。
   强约束：一次只处理一门课；必须有真实课程材料；低置信信息进 `to-confirm` 不默默合并。

## 结论：重叠的是形式，错开的是命题

| | 女娲补天 | 本项目 |
|---|---|---|
| 前置条件 | 必须有材料 | **一张照片** |
| 动作 | 全量覆盖（建骨架→压缩→自测→回补） | **裁剪**（决定不学什么） |
| 输出 | 一份完整复习包 | 三份不等的清单 |
| 个性化 | 材料差异 | 目标分数 × 学校难度 × 剩余天数 |

一句话：**它们解决"怎么学会"，我们解决"哪些不用学"。**

## 决定直接借鉴的两条

1. `to-confirm` 机制：照片定位不准时，不给结论，给"疑似第 X 章，请确认"。
   理由：错误定位会让后面全部内容都错，而且用户无法察觉。
2. 证据分级：联网内容只补骨架或解释，不替代老师材料。
   理由：老师划的重点才是本课程的"真相来源"。

## 两个技术难点的拆解

**照片 → 知识**

不要当作文本处理。拆两路：
- 文字路：OCR 出章节号/标题 → 与章节骨架做模糊匹配（编辑距离 + 编号正则）
- 视觉路：颜色分割检测荧光笔/下划线 → 得到"被标记的行区间"
- 两路交叉得到"章节 + 重点条目"，置信度低于阈值则走 `to-confirm`

**资料 → 个人化**

个人化不靠"记住偏好"，靠四个显式参数（目标分 / 学校档位 / 剩余天数 / 每日可用时长）。
转化三段式：一句话定义 + 一个必考题型 + 一个最常见错误；超出 `depth_cap` 的内容降级为
"了解即可，不考推导"。这样同一知识点的产出在 985 与普通本科之间不同，但差异可解释。

## 复现要求（新增）

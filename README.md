# 划重点 · 大学物理期末复习助手

> 拍一张老师划的重点，得到一份「考 50 / 60 / 80 分分别该学什么」的裁剪清单。

## 这是什么

大学物理的期末资料比高数少得多，同学真正的问题不是「找不到题」，而是：

1. 老师划了一整本书，**不知道哪些该放弃**；
2. 教材讲得太深，**只想不挂科的人被劝退**；
3. 不同学校难度差很多，**985 的复习范围直接套到二本会浪费时间**。

本项目把一个学期的复习范围，按「目标分数 × 学校难度」编译成三份**裁剪过的**知识点清单，并为每份清单配上检测题。

## 为什么不是拍照搜题

| | 拍照搜题 | 本项目 |
|---|---|---|
| 输入 | 一道题 | 一张目录 / 重点页 |
| 输出 | 这道题的答案 | 这门课该学什么、学到多深 |
| 深度 | 无约束 | 由 `depth_cap` 硬约束 |
| 个性化 | 无 | 目标分数 + 学校画像 |

## 和同类项目的区别

| | DeepTutor | 女娲补天（nuwa-mends-the-sky） | 本项目 |
|---|---|---|---|
| 前置条件 | 要自己整理文档 | **必须有课程材料**（PPT/讲义/教材/作业/题库至少一样） | **一张照片** |
| 核心动作 | 讲解、陪练、追踪掌握度 | 建骨架 → 压缩 → 自测 → 回补（全量覆盖） | **按分数线裁剪** |
| 输出 | 学习过程 | 一份完整复习包 | 三份**不等**的清单 |
| 个性化维度 | 学习历史 | 材料差异 | 目标分数 × 学校难度 × 剩余天数 |
| 形态 | 自托管 Web | Codex skill | 网页 |

一句话：**它们解决「怎么学会」，本项目解决「哪些不用学」。**

借鉴自同类项目的两条原则（写进设计）：

1. **低置信信息进 `to-confirm`，不默默合并** —— 照片定位不准时必须让用户确认。
2. **外部资料只能补骨架或解释，不能替代老师材料** —— 联网检索是补充，不是真相来源。

## 核心技术难点

| 难点 | 做法 |
|---|---|
| 一张照片 → 章节 | 双路：OCR 抓章节号/标题做模糊匹配 + 视觉检测荧光笔/下划线定位被标记行 |
| 搜到的资料 → 个人化 | 四参数（目标分/学校/剩余天数/每日时长）+ 三段结构（定义/必考题型/常见错误）+ `depth_cap` 截断 |

## 核心流程

```
拍目录/重点页
  → OCR + 目录结构化（章节树）
  → 章节映射到知识点库
  → 分层打分（真题频次 × 分值权重 × 认知成本 × 学校难度系数）
  → 三档清单（50 / 60 / 80）
  → 检测题
  → 答错 → 回退到前置知识点 → 重排
```

## 技术栈

- 后端：Python + FastAPI + SQLite（单机、零运维）
- 检索：`bge-m3`（dense + sparse 一体）
- 识别：PaddleOCR（本地）
- 生成：DeepSeek API
- **内容来源：联网检索 + 落盘缓存**（不依赖下载教材 PDF）
- 前端：Next.js 单页（后续）

刻意**不使用 Dify**：本项目的核心是确定性的打分与裁剪算法，需要可测试、可解释、可复现，工作流编排不满足这三点。

## 目录结构

```
backend/
  app/           API 与领域模型
  db/schema.sql  数据表定义（唯一事实来源）
data/
  raw/           教材 PDF、真题（不入库、不进仓库）
  curriculum/    课程章节原始表
  app.db         SQLite（运行时生成，不进仓库）
docs/
  prompts/       与 AI 协作的 Prompt 历史快照（比赛要求）
```

## 快速开始

**Windows 一键（推荐）**

```powershell
powershell -File scripts/bootstrap.ps1
```

**手动**

```bash
pip install -r backend/requirements.txt
python scripts/check_db.py
python -m uvicorn backend.app.main:app --port 8000
```

健康检查：`GET http://127.0.0.1:8000/health`

**每天收工（保持细粒度提交历史）**

双击 `scripts/push.bat`，或执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/daily_push.ps1
```

> Windows 默认禁止运行 .ps1（`Restricted` 策略），所以必须带 `-ExecutionPolicy Bypass`，
> 或者直接用 `push.bat` / `ocr.bat` 这些封装好的入口。

首次使用需配一次远端与代理：

```bash
git remote add origin https://github.com/<用户名>/<仓库名>.git
git config --global http.proxy http://127.0.0.1:7897
```

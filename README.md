# 划重点 · 大学物理期末复习助手

> 拍一张老师划的重点，得到一份「考 50 / 60 / 80 分分别该学什么」的裁剪清单。

## 这是什么

大学物理的期末资料比高数少得多，同学真正的问题不是「找不到题」，而是：

1. 老师划了一整本书，**不知道哪些该放弃**；
2. 教材讲得太深，**只想不挂科的人被劝退**；
3. 不同学校难度差很多，**985 的复习范围直接套到二本会浪费时间**。

本项目把一个学期的复习范围，按「目标分数 × 学校难度」编译成三份**裁剪过的**知识点清单，并为每份清单配上检测题。

## 为什么不是拍照搜题

| | 拍照搜题 | 本项目 |
|---|---|---|
| 输入 | 一道题 | 一张目录 / 重点页 |
| 输出 | 这道题的答案 | 这门课该学什么、学到多深 |
| 深度 | 无约束 | 由 `depth_cap` 硬约束 |
| 个性化 | 无 | 目标分数 + 学校画像 |

## 核心流程

```
拍目录/重点页
  → OCR + 目录结构化（章节树）
  → 章节映射到知识点库
  → 分层打分（真题频次 × 分值权重 × 认知成本 × 学校难度系数）
  → 三档清单（50 / 60 / 80）
  → 检测题
  → 答错 → 回退到前置知识点 → 重排
```

## 技术栈

- 后端：Python + FastAPI + SQLite（单机、零运维）
- 检索：`bge-m3`（dense + sparse 一体）
- 识别：PaddleOCR（本地）
- 生成：DeepSeek API
- 前端：Next.js 单页（后续）

刻意**不使用 Dify**：本项目的核心是确定性的打分与裁剪算法，需要可测试、可解释、可复现，工作流编排不满足这三点。

## 目录结构

```
backend/
  app/           API 与领域模型
  db/schema.sql  数据表定义（唯一事实来源）
data/
  raw/           教材 PDF、真题（不入库、不进仓库）
  curriculum/    课程章节原始表
  app.db         SQLite（运行时生成，不进仓库）
docs/
  prompts/       与 AI 协作的 Prompt 历史快照（比赛要求）
```

## 快速开始

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r backend/requirements.txt
python -m backend.app.main          # 或 uvicorn backend.app.main:app --reload
```

健康检查：`GET http://127.0.0.1:8000/health`
